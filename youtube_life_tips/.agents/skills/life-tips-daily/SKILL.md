# Daily life-tips Short

This workflow is restricted to the `youtube_life_tips` folder. Do not inspect, modify, or reuse assets or credentials from the parent Peace in Mind project.

## Schedule and control

- Windows Task Scheduler starts the mailbox watcher at logon and enqueues releases at 03:00 and 15:00 Korea Standard Time. Morning release keys are `YYYY-MM-DD`; evening keys are `YYYY-MM-DD-pm`.
- The watcher launches Codex CLI stages only when work exists. It uses short-lived, separate main, review, and developer sessions with file handoffs; it does not rely on Codex Scheduled or a permanently open Codex desktop window.
- The 06:30/18:30 KST cutoffs are strict for the 07:00/19:00 releases. If the PC is off/asleep at the corresponding start, that release is skipped without catch-up.
- Missing login, quota, Internet, ImageGen, channel OAuth, local TTS, FFmpeg, or any review/validation means skip; never try a different channel or credentials.

## Required sequence

1. Read the project's `EDITORIAL_BRIEF.md` before selecting a topic for an automatic or manual draft. Use the current Asia/Seoul date and the Korean season: spring March-May, summer June-August, autumn September-November, winter December-February. Review `work/sample/metadata.json` and previous `work/daily/*/content.json`. Avoid repeating the same practical tip, core claim, solution sequence, or distinctive hook. A broad household task category may recur when the actual advice remains useful and distinct.
2. Search for useful household tips relevant to the current season first. Verify key facts using at least two reliable sources, preferably primary sources. If no seasonal tip is both well-supported and genuinely useful, choose a season-neutral topic and state the reason in `fallback_reason`. Do not force a seasonal angle. Set `topic_strategy` to `seasonal` or `evergreen_fallback`.
3. Use the same result-first standard for manual samples and scheduled releases. One worthwhile transformation may have one supported decision point; do not invent extra branches or pad a short technique. Keep the shared YouTube/TikTok video above one minute by selecting a demonstration that earns 65-90 seconds. Write a new, conversational Korean script as a continuous spoken_script, then split into concise scenes at natural meaning boundaries, 65-90 seconds total as defined in `video_limits.py`. For every new or revised draft, establish the takeaway and explanation order first, then apply the repository-local im-not-ai skill at `../.agents/skills/humanize-korean/SKILL.md` relative to the `youtube_life_tips` project directory before splitting into scenes. This skill and its bundled references are the permitted parent-folder writing references; all generated output stays inside `youtube_life_tips`. Recheck meaning and sentence connections after the style pass, and keep diagnostics outside narration and automated JSON responses. Record the ordinary approach, a sourced non-obvious decision that materially changes the viewer's action, and why the difference matters in `viewer_value`. Generic advice such as putting fruit in a refrigerator or folding clothes into a drawer does not pass; adding a fact that leaves the action unchanged does not rescue it. Read all scene narrations as one spoken script and remove abrupt transitions, repeated advice, and a filler ending. Do not copy source wording or any reference video's words, images, thumbnail, audio, or sequence. Keep verified source titles and URLs in internal source records only. The public YouTube description contains a concise viewer summary without references, citations, or source URLs. Do not render source credits into the video.
4. A separate review session independently verifies sources and claims, safety, concrete viewer value, natural narration flow, content-level originality, scene structure, and whether the seasonal choice or fallback is justified. Repair editorial issues and re-review before ImageGen (up to two revisions). Stop only if issues remain unresolved or facts/safety are unverified.
5. The main session incorporates review findings and approves the final plan. It must retain at least two HTTPS source records and the seasonal decision fields.
6. Invoke the built-in `$imagegen` exactly once per candidate for a new high-resolution portrait 3:4 storyboard (for example 1536x2048; minimum 768x1152 and height/width at least 1.25). Use two columns for up to eight scenes, otherwise three, with ceil(scene_count/columns) rows and one distinct panel per scene; unused cells stay blank. The scene count follows the explanation. Use AI-photorealistic hand-action photographs like the accepted T-shirt-bag sample: consistent objects, critical manipulation closeups, intermediate states and a finished result. Keep vector/cartoon sequences out of the default format. Use short per-scene heading text and readable captions; the renderer adds AI 재현. Save as `work/daily/RELEASE-KEY/storyboard.png`, with no text, captions, logos, or watermark in the source image. Do not reuse sample, previous daily, or source images. If ImageGen fails or cannot save, stop; do not substitute downloaded assets, code-drawn scenes, or another image API.
7. Save `content.json` including `slot` (`am` or `pm`) and run `python render_daily.py --date YYYY-MM-DD --slot am|pm`. The renderer uses local Edge TTS and 720x1280/15fps output with one FFmpeg thread. Missing packages, TTS/render errors, unreadable captions, wrong dimensions, missing audio, or duration outside the range in `video_limits.py` mean stop.
8. Main performs an independent final audit of the storyboard, approved script, sources, seasonal choice/fallback, video metadata, duration, dimensions, and audio. Do not upload unless every check passes. For automatic and manual renders, finish the TikTok handoff in the project README with `codex_mailbox.save_tiktok_copy(video_path, day, slot)` and confirm the dated MP4 exists before reporting completion.
9. Run `python upload_daily.py --date YYYY-MM-DD --slot am|pm` before the slot's cutoff. It verifies the exact channel in `state/config.local.json` and schedules the selected release. Never upload to another channel or attempt a late/catch-up post.
10. Write the result to `work/mailbox/outbox/RELEASE-KEY.json`: `scheduled`, `skipped`, or `failed`, with URL or a specific reason. The mailbox runner owns email delivery.

## Resource limits

- Keep PIM production and settings unchanged. Unattended runs launch no browser or persistent preview server. When a manual task explicitly starts a preview, record the exact session/PID and project command line, then stop only that owned server after render/review/export on success or failure and verify exit. Never stop another project's process or kill by port alone.

- Up to three candidates per release, exactly one NEW storyboard generation per candidate, and at most one published video per release. A candidate may receive at most two targeted built-in ImageGen edits of failed panels, each recorded separately and followed by independent final review; preserve all unaffected panels and approved narration. Never repeat an uncertain edit. After a candidate fails final review, attempt up to two safe wording/layout or targeted visual revisions with independent re-review. When picture errors alone lower density or viewer-pull scores, repair those pictures first while preserving the approved script; every final check must still pass. If it still fails or cannot be safely repaired, preserve its assets, exclude its topic, and start a new script and storyboard on a different topic. Cancel after the third rejected candidate. Infrastructure/auth/quota failures stop without consuming more image calls. Run stages serially.
- Use 720x1280, 15 fps, one FFmpeg/x264 thread. Keep assets and intermediate files under `work/daily/`.
- Do not install packages during a daily run. Use the existing `work/vendor` local Edge TTS package.
- Never commit credentials, OAuth tokens, generated videos, or daily output.

## Comprehension and layout repair

Write spoken_script before splitting scenes; the ordered scene narrations must reproduce it without losing transitions. Use the number of scenes the explanation needs, never force four. Every scene needs visual_action matching its object, state, and instruction. The reviewer must return viewer_recap, scene_count, and transition_checks for every adjacent pair (from_scene, to_scene, clear, evidence quoting actual wording). Do not infer missing steps from the description or sources. Check the complete final on-screen text, not merely legibility.

Before ImageGen, measure the text at the real rendering widths. Reflow and resize within readable limits, then revise long wording or split scenes if needed, up to two revisions with independent review. Never silently truncate words or omit conditions to fit. Generate the grid, narration clips, and audit contact sheet for the resulting scene count. New uploads set containsSyntheticMedia=true.
