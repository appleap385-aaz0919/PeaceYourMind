# 생활꿀팁 YouTube Shorts

2026-11-10 이후 새로 제작하는 수동·예약 영상은 사용자가 확인한 티셔츠 가방 샘플 방식으로 만듭니다. AI 실사풍으로 손과 물건의 작업 과정·중간 변화·완성 결과를 크게 보여주고, 장면별 제목과 자막 및 `AI 재현` 표시를 적용합니다. 자동 렌더 화면도 샘플과 같은 짙은 녹색 배경과 큰 사진 영역으로 맞췄습니다. 구체적인 소재·시연 기준은 `EDITORIAL_BRIEF.md`를 따릅니다. PIM 제작 방식·채널·예약·인증 설정은 변경하지 않습니다.

자동 제작은 미리보기 서버나 브라우저를 띄우지 않습니다. 수동 작업에서 미리보기 서버가 필요해 직접 실행했다면 해당 세션의 PID·명령줄·프로젝트 경로를 기록하고, 제작·검수·저장 후 성공·실패에 관계없이 그 서버만 종료해 종료 여부를 확인합니다. 다른 프로젝트 서버나 같은 포트를 쓰는 불명확한 프로세스는 종료하지 않습니다.

최종 검수에서 탈락한 영상은 최대 두 번 보정·재검수합니다. 그래도 탈락하거나 안전한 보정이 불가능하면 실패 소재를 제외하고 다른 소재의 대본·그림부터 다시 제작합니다. 첫 제작을 포함해 최대 3개 후보까지만 진행하며, 세 번째 후보도 탈락하면 `cancelled`로 종료합니다. 실패한 산출물은 `work/daily/RELEASE-KEY/rejected-candidates/`에 보존합니다. 인증·사용량 제한·통신 오류는 이 소재 교체 규칙으로 우회하지 않습니다.

명시적으로 요청한 즉시 게시에는 `python codex_mailbox.py enqueue --today --publish-now --editorial-instruction "주제 지시"`를 사용합니다. 즉시 게시 산출물은 `YYYY-MM-DD-manual`로 구분되어 오전·오후 정규 회차와 충돌하지 않습니다. 검수를 모두 통과한 영상만 예약 없이 공개하며 AI 라벨을 설정합니다. 같은 날짜의 즉시 게시 요청은 중복 업로드하지 않습니다.

감시기 실행 버전과 PID는 `state/watcher-version.json`에 기록합니다. 감시기 코드가 변경되면 진행 중인 작업을 마친 후 종료하고 Windows 작업 스케줄러의 재시작 설정을 통해 새 코드를 읽습니다.

이 자동화는 이 폴더 안의 Codex CLI, 파일 우편함, Windows 작업 스케줄러만 사용합니다. Codex CLI는 이미 설치된 `D:\Tools\Codex`를 사용합니다. 예약 실행 중 Codex 데스크톱의 Scheduled 작업을 따로 띄우지 않으며, 일이 있을 때만 Codex 세션을 순서대로 실행합니다.
예약 작업은 `pythonw.exe`로 실행하고, 감시기와 렌더러가 실행하는 Codex·FFmpeg 등의 자식 프로세스에는 Windows 콘솔 창을 만들지 않는 옵션을 적용합니다. 실행 결과와 오류는 기존 로그에 기록됩니다.

## 매일 실행

신규 업로드는 오전·오후 모두 `status.containsSyntheticMedia=true`를 설정해 YouTube의 AI 콘텐츠 라벨을 적용합니다. 이미 업로드한 영상은 변경하지 않습니다.

- Windows 작업 스케줄러가 로그인할 때 파일 감시기를 시작하고, 매일 03:00과 15:00(한국 시간)에 각각 오전·오후 회차의 요청을 만듭니다. 업로드 마감은 각각 06:30과 18:30입니다.
- 메인 작성, 독립 검수, 시각 자료 제작, 최종 감사 단계를 별도 Codex CLI 실행으로 처리합니다. 단계 사이의 전달 내용은 `work/mailbox/runs/`와 `work/daily/`의 파일로 남습니다.
- 모든 확인이 통과하면 서로 다른 영상 두 편을 전용 YouTube 채널에 비공개로 올려 07:00과 19:00에 공개되도록 예약합니다. 각 회차의 마감을 넘기면 해당 회차만 건너뜁니다.
- 최종 결과(예약 성공, 건너뜀, 실패)는 `appleap385@gmail.com`에서 게재 결과 수신 메일 `aaz0919@naver.com`으로 발송합니다. 처음 한 번 `.\configure_email.ps1`을 실행해 Gmail 앱 비밀번호를 숨김 입력하고 테스트 메일을 확인해야 합니다. 비밀번호는 현재 Windows 계정에서만 복호화되는 DPAPI 형식으로 `state/`에 저장됩니다.
- PC가 03:00 또는 15:00에 꺼져 있거나 절전 중이거나 Windows 사용자 세션이 로그인되어 있지 않아 시작하지 못한 경우에는 해당 회차를 건너뛰며 보충하지 않습니다. 일시적인 통신·서비스 오류는 아래 복구 규칙으로 재시도합니다. 인증 취소, 품질 검수 실패, ImageGen 실패 등은 자동 재생성으로 우회하지 않습니다.
- Windows 사용자 계정은 로그인 상태로 두어야 하지만 화면은 `Win+L`로 잠가도 됩니다. PC는 켜져 있고 절전·최대 절전 상태가 아니며 인터넷에 연결되어야 합니다. 재부팅 후에는 Windows에 다시 로그인해야 감시기가 시작됩니다.
- Codex CLI는 단계가 실행되는 동안만 프로세스로 뜹니다. 감시기는 로그인 상태에서 가벼운 파일 확인만 수행합니다. Codex 데스크톱 앱의 창을 계속 열어둘 필요는 없습니다. CLI 로그인과 사용 한도는 필요합니다.

## 오류 재시도와 중단 복구

- 회차별로 최초 실행 포함 최대 3회 시도합니다. 일시 오류 뒤 1분, 다음 오류 뒤 3분을 기다리며 06:30/18:30 이후 해당 회차의 새 업로드를 시작하지 않습니다. 단계 제한시간도 남은 준비 시간 안으로 줄입니다.
- Windows 큐 작업은 인터넷이 잠깐 끊겨도 요청을 남길 수 있습니다. 감시기는 오류 종료 시 1분 간격으로 최대 3회 다시 시작하도록 등록합니다.
- 승인된 단계와 검증된 영상은 재사용합니다. 이미지 생성 호출 전에 시도 기록을 저장하므로 완료 여부가 불분명한 이미지 생성을 다시 호출하지 않습니다.
- 업로드 세션은 무시되는 `work/daily/YYYY-MM-DD/upload_session.json`에 보관합니다. 재시작 시 서버가 확정한 수신 위치를 조회해 이어 보내며, 파일·채널·예약 조건이 바뀌면 새 업로드로 대체하지 않습니다. 세션 파일에는 비공개 업로드 URL이 있으므로 공유하거나 커밋하지 않습니다.
- `upload.json` 성공 영수증을 실패 보고보다 우선합니다. 업로드 후 문자 출력 오류가 성공을 덮지 않도록 UTF-8 실행과 ASCII-safe 결과 출력을 사용합니다. 메일 발송도 최대 3회 시도합니다.
- 세션이 만료됐거나 완료 여부를 확인할 수 없으면 중복 방지를 위해 멈춥니다. 이때 `upload.json`/`upload_session.json`을 삭제해 재실행하지 말고 먼저 YouTube의 기존 영상을 대조해야 합니다.

## 계절 우선 주제 선정

한국 계절에 맞는 생활 정보를 먼저 검색합니다. 봄은 3~5월, 여름은 6~8월, 가을은 9~11월, 겨울은 12~2월로 봅니다. 창작자 영상, 실무자 글, 소비자 보도, 커뮤니티 질문·후기 등 폭넓은 자료에서 반복되는 불편과 실용적인 질문을 찾습니다. 기관 자료가 아니라는 이유만으로 후보에서 제외하지 않습니다. 실제 사실 주장은 서로 독립된 두 곳 이상으로 확인하고, 저위험 생활 팁은 맥락이 분명한 실무자·창작자 자료도 교차 확인에 사용할 수 있습니다. 기기별·화학·건강·안전 주장은 적절한 제조사·전문 기술 자료로 확인하고, 개인 경험을 보편적 사실처럼 쓰지 않습니다. 출처마다 뒷받침하는 주장을 기록하고, 같은 자료를 재게시한 페이지는 별도 출처로 세지 않습니다. 시청자의 행동을 바꿀 만큼 유용한 주제를 우선 구성하며, 그런 계절 주제가 없을 때는 계절과 무관한 생활 팁으로 전환하고 대체 사유를 기록합니다. 계절에 억지로 맞추거나 근거를 만들어내지 않으며, 검수 세션에서도 이 선택을 다시 확인합니다.

대본에는 흔히 하는 방법과 그보다 나은 구체적 판단, 그 차이가 중요한 이유를 기록합니다. 주제의 실용성과 새로움은 모델의 점수만으로 인정하지 않습니다. 후보별로 서로 다른 사람이나 출처에서 반복된 실제 질문·불편을 두 건 이상 링크와 함께 제시하고, 이는 수요 신호로만 취급합니다. 사실 근거는 별도로 확인합니다. 핵심 답이 '제품 라벨/설명서를 읽고 그대로 하세요'인 주제는 탈락시킵니다. 라벨은 더 큰 진단에서 한 분기일 수 있지만 핵심 통찰이 될 수 없습니다. 평범한 보관·정리·청소 조언도 시청자의 결정을 바꾸고 구체적인 시간·비용·실패를 줄인다는 근거가 없다면 채택하지 않습니다.

주제 선정 전에 식품·의류·청소·집안 관리 등 서로 다른 분야의 후보를 비교합니다. 최근 식품 영상이 세 편 이상 연속되면 근거와 실용성이 동등한 비식품 후보를 우선합니다. 약한 팁을 채우기 위한 분야별 할당량은 두지 않습니다. 생성된 그림의 가로 구분선 위치를 감지해 장면을 분할하고, 다른 장면이 섞이면 최종 검수에서 거릅니다.

연속된 설명인 `spoken_script`를 먼저 쓰고, 의미와 행동 단위에 맞춰 장면을 나눕니다. 장면 수는 네 개로 고정하지 않으며 전체 영상은 틱톡 공용 업로드를 고려해 65~90초입니다. 결과를 재현하는 데 필요한 시연과 설명으로 길이를 채우며, 준비 동작이나 말 반복으로 늘리지 않습니다. 그림 생성 전에 실제 TTS 음성 길이를 측정하고 범위를 벗어나면 대본을 보정·재검수합니다. 장면별 `visual_action`에는 대상·상태·행동을 명시합니다. 검수자는 처음 보는 시청자의 입장에서 내용을 다시 설명하고, 모든 장면 사이의 실제 연결 문구를 근거로 검사합니다. 중요한 조건을 설명란으로만 넘기지 않습니다.

## 틱톡 수동 업로드용 파일

최종 영상 검수를 통과하면 `tiktok_uploads/YYYY-MM-DD/life-tip-YYYY-MM-DD-am.mp4` 또는 `life-tip-YYYY-MM-DD-pm.mp4`에 원본 MP4를 복사합니다. 즉시 게시 회차는 파일명 끝에 `manual`을 사용합니다. 이 폴더는 Git에 포함되지 않으며, 틱톡 업로드는 직접 진행합니다. 유튜브 예약·즉시 업로드는 기존 자동화가 계속 처리합니다. 틱톡에 올릴 때 AI 제작 콘텐츠 표시를 켜세요.

자동 회차와 수동 제작 모두 `codex_mailbox.save_tiktok_copy(video_path, day, slot)`를 사용해 날짜별 폴더에 최종 MP4를 저장하고, 파일이 존재하는지 확인한 뒤 실제 경로를 안내합니다. `work/daily/`의 제작 산출물과 별도로, 틱톡 전달용 파일은 이 날짜별 폴더를 기준으로 관리합니다.

같은 이름의 파일이 이미 있으면 기존 영상을 보존하고 `-2`, `-3`을 붙여 저장합니다. 같은 영상의 저장을 다시 실행하면 내용이 일치하는 기존 파일을 사용합니다.

글이 길면 줄바꿈과 읽을 수 있는 범위의 글자 크기(제목 36px 이상, 본문 30px 이상)를 자동 조정합니다. 그래도 맞지 않거나 흐름이 어색하면 이미지 제작 전에 대본·자막을 다듬거나 장면을 늘려 최대 두 차례 수정하고 독립 재검수합니다. 문장 뒷부분을 잘라내지 않습니다. 수정 후에도 사실·의미·가독성이 확보되지 않을 때만 해당 회차를 보류합니다. 이미지 격자와 음성 구간, 최종 검수 화면도 실제 장면 수에 맞춰 생성합니다.

모든 영상은 새 한국어 대본과 새 ImageGen 장면으로 만듭니다. ImageGen은 회차별 한 번, 정기 작업 기준 하루 최대 두 번 사용합니다. 한도 초과나 생성 실패 때 다른 이미지 API, 내려받은 사진, 코드 그림으로 대신하지 않고 해당 회차를 건너뜁니다. Gemini API를 사용하지 않습니다. 내레이션은 `edge-tts` Python 클라이언트로 Microsoft의 온라인 한국어 TTS 서비스를 호출하고, 렌더링은 720x1280, 15fps, FFmpeg 한 스레드로 제한합니다.

## 현재 설정

이 PC에는 채널 ID와 OAuth 토큰, 이메일 알림이 설정되어 있습니다. 작업 등록 스크립트는 기존 03:00 작업과 감시기에 15:00 오후 작업을 추가합니다. 오전 산출물·원장은 기존 `YYYY-MM-DD` 이름을 유지하고 오후는 `YYYY-MM-DD-pm`으로 구분합니다. 같은 날짜의 오전 영상도 오후 대본의 중복 검사에 포함합니다.

## 최초 설정 또는 복구

새 PC에서는 아래 채널 ID와 OAuth 설정을 끝내기 전에는 작업을 등록하지 않습니다.

1. PowerShell에서 `youtube_life_tips` 폴더로 이동해 `.\setup_codex.ps1`을 실행합니다. 기존 `D:\Tools\Codex`의 CLI 경로와 ChatGPT 로그인 상태만 확인하며 프로젝트 안에 CLI를 설치하지 않습니다.
2. `config.local.example.json`을 `state/config.local.json`으로 복사하고 생활꿀팁 전용 YouTube 채널 ID를 입력합니다. PIM 채널 ID는 쓰지 않습니다.
3. 생활꿀팁 채널을 관리하는 Google 계정의 OAuth 데스크톱 클라이언트 JSON을 `state/google_oauth_client.json`에 복사하고, 해당 Google 계정으로 OAuth 테스트 사용자 등록 및 `youtube.upload`, `youtube.readonly` 권한 설정을 완료합니다.
4. 이 폴더에서 `python authorize_youtube.py`를 실행하고 브라우저에서 해당 계정을 인증합니다. 출력된 채널 ID가 `state/config.local.json`의 ID와 정확히 같은지 확인합니다. 자격 증명과 토큰은 `state/` 아래에만 두며 Git에 올리지 않습니다.
5. Python 3, `ffmpeg`, `ffprobe`, 기존 `work/vendor` Edge TTS 및 Pillow가 준비되어 있는지 확인합니다.
6. 등록 전 점검: `python codex_mailbox.py doctor --require-youtube`
7. 점검이 통과하면 PowerShell에서 `.\register_tasks.ps1`을 실행합니다. 감시기와 03:00·15:00 작업이 등록됩니다. 해제할 때는 `.\unregister_tasks.ps1`을 실행합니다.

작업 등록 스크립트는 모든 사전 점검이 통과하지 않으면 작업을 하나도 등록하지 않습니다. Windows 시간대가 `Korea Standard Time`인지도 확인합니다. 작업 결과는 `work/mailbox/outbox/YYYY-MM-DD.json`, 감시 로그는 `work/mailbox/logs/watcher.log`, 이메일 오류는 `work/mailbox/logs/email.log`에서 확인할 수 있습니다. 이메일 설정은 YouTube OAuth 설정 후 `.\configure_email.ps1`을 실행해 완료합니다. Google 계정 비밀번호가 아니라 Google 앱 비밀번호를 입력하며, 입력값은 화면에 표시되지 않습니다.

## 제작·저작권 원칙

- 창작자·커뮤니티 자료는 실제 문제와 질문을 발견하는 자료로 폭넓게 활용할 수 있습니다. 객관적 사실은 독립 자료로 확인하고, 개인 경험은 경험담으로 한정해 표현합니다. 기기별·화학·건강·안전 주장은 제조사 또는 전문 기술 자료로 확인합니다.
- 출처 문장과 사진·영상·음성은 복사하지 않습니다. 아이디어·사실을 참고하더라도 대본, 훅, 제목, 장면 순서, 그래픽·표현은 독립적으로 만듭니다. 특정 창작자의 고유한 구성이나 표현을 가깝게 재현하지 않으며, 출처 링크는 이용 허락을 대신하지 않습니다. 출처 제목과 링크는 검증용 내부 기록에만 남깁니다. 유튜브 설명에는 영상 내용만 요약하며 참고자료·인용·출처 링크를 넣지 않습니다. 영상 화면에도 출처를 표시하지 않습니다.
- 저작권과 유튜브의 재사용·비진정성 콘텐츠 수익화 심사는 별개입니다. 단순 바꿔 말하기나 AI 그림 추가만으로 충분하다고 보지 않고, 영상마다 독창적인 설명·판단·교육적 효용을 담으며 거의 같은 틀을 대량 반복하지 않습니다.
- 의료 진단·치료, 법률·금융 조언, 위험한 화학 혼합, 전기·가스 수리 등 위험한 주제는 자동 게시하지 않습니다.
- 생성 영상, OAuth 정보, 매일 작업 산출물은 커밋하거나 푸시하지 않습니다.


사전 점검 중 일시적인 실행·연결 오류는 실제 제작 시도 3회와 분리해 최대 6회 재시도합니다. 재시도 간격은 1분부터 늘리되 최대 30분이며, 06:30·18:30 마감 이후로 넘기지 않습니다. Codex 버전 확인은 최대 60초 대기하며 같은 실행 파일은 감시기 프로세스 안에서 재확인을 생략하고 파일이 바뀌면 다시 검사합니다. 인증 누락이나 비일시적 오류는 계속 차단합니다.
# 제작 재탐색과 로컬 검수 실행

소재 미선정도 기존 회차당 최대 3개 후보 예산 안에서 새 조사로 이어집니다. 이전 조사와 탈락 이유를 다음 단계에 전달하며, 유용한 소재를 예상 길이만으로 제외하지 않습니다. 완전한 대본을 쓴 뒤 실제 Edge TTS 길이를 측정하고, 재현에 빠진 동작 설명만 보완합니다. 완성된 설명이 실제로 짧다면 다른 소재를 찾습니다.

수동 제작도 `codex_mailbox.process_request`를 사용하면 예약 제작과 동일한 원문 검증, 점수 검수, 음성 길이 측정, 이미지 생성, 최종 영상 검수와 TikTok 저장 절차를 거칩니다. 요청 JSON의 `render_only: true`는 게시 옵션과 함께 사용할 수 없으며, 업로드 전에 검수된 MP4와 TikTok 복사본만 저장합니다. 이 모드에는 예약 업로드 마감 시각을 적용하지 않습니다. 일반 예약 회차의 마감과 게시 동작은 유지됩니다.
