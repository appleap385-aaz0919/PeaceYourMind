# data/krv — 개역한글(1961) 원문 데이터 출처

> 이 디렉터리의 파일은 **구절 본문 대조의 기준**이다.
> `scripts/verify_verses.py`가 `verses.yaml`의 `text`를 여기에 대조해
> `verified` 판정을 내린다. 이 파일이 바뀌면 모든 판정의 근거가 바뀐다.

### 형식

```json
[ { "book": "Psalms",
    "chapters": [ { "chapter": 46,
                    "verses": [ { "verse": 10, "text": "이르시기를 너희는 …" } ] } ] } ]
```

- 책 키는 영문(`Psalms`, `1Peter`, `SongofSolomon`). 한글 ↔ 영문 매핑은

  검수 결과와 맞는 형식이다 (아래 "왜 이 데이터인가" 3번 참조).

## 왜 이 데이터인가 — 채택 근거

후보 데이터가 진짜 개역한글(1961)인지는 **옛 표기 보존 여부**로 갈린다.
현대 맞춤법으로 "고친" 사본은 개역한글이라는 이름을 달고 있어도
동일성유지권 관점에서 다른 저작물이며, 대조 기준이 될 수 없다.
(`verses.yaml` 헤더 참조)

### 1. 정답지 6구절 — 전건 일치

이미 웹 원문 대조가 끝난 6구절(`verses.yaml`의 `verified: true` 항목)과
한 글자 단위로 대조해 **6/6 일치**했다.

| 참조 | 판별 지점 |
|---|---|
| 시편 46:10 | **"알찌어다"** — 개역개정·현대화 사본은 "알지어다" |
| 베드로전서 5:7 | **"권고하심이니라"** — 개역개정은 "돌보심이라" |
| 이사야 43:1 | "이제" 2회 — 초안에서 1회 누락됐던 지점 |
| 시편 46:1 | 표제 미포함, 1절 단독 — 절 경계 오류가 났던 지점 |
| 시편 131:2 | 일치 |
| 이사야 41:10 | "도와 주리라" (띄어쓰기 포함 일치) |

### 2. 탈락시킨 후보

**`yuhwan/Bible-krv`** (GitHub 10 stars, 한글 책 이름 JSON)
→ 시편 46:10이 **"알지어다"**. 현대화된 사본이다. 정답지 불일치로 탈락.
   시편 46:1에 표제(`[고라 자손의 시, 영장으로…]`)가 본문에 섞여 있는 것도
   대조 기준으로 부적합했다.

### 3. 제2 소스 교차 검증 — 그리고 그것이 심판관이 될 수 없었던 이유

독립 소스 `scj-peter/HolyBibleKRV`(`개역한글_KRV_국문.sql`, 31,102절)를
받아 전수 비교했다. 결과는 두 소스가 **26.4% 불일치**(공백 차이 17.5%,
글자 차이 8.8%)였고, 이 차이가 어느 쪽 문제인지 옛 표기 분포로 갈렸다.

| 옛 표기 | 채택본 | scj-peter |
|---|---:|---:|
| `-ㄹ찌라도` | 263 | **2** |
| `-ㄹ찌니라` | 461 | **2** |
| `세째` | 46 | **1** |
| `네째` | 37 | **1** |
| `가라사대` | 778 | 776 |

`-ㄹ찌라도`·`-ㄹ찌니라`가 통째로 사라지고 `세째/네째`가 `셋째/넷째`로
바뀐 것은, scj-peter 판본이 **부분적으로 현대 맞춤법화된 사본**이라는 뜻이다.
(`-ㄹ찌어다`만 486건 남아 있어, 정답지에 쓴 시편 46:10 한 건만으로는
이 결함이 드러나지 않았다 — 표본 검사의 한계를 보여주는 사례다.)

→ **제2 소스는 옛 표기 판정에 쓸 수 없다.** 이 저장소에 넣지 않았다.

### 4. "-ㄹ지어다 / -ㄹ찌어다" 혼재는 결함이 아니라 원문 그대로다

2차분 큐레이션(2026-08-18) 중 채택본에서 일관성이 깨진 것처럼 보이는 지점을 찾았다.

```
시편  46:10   내가 하나님 됨을 알찌어다     (찌)
시편   4:3    너희가 알지어다               (지)   ← 같은 어간인데 다르다
시편 116:7    네 평안함에 돌아갈지어다      (지)
```

채택본 전체 분포도 갈린다: `-ㄹ찌어다` 461건, `-ㄹ지어다` 30건
(`-ㄹ찌라도` 263 / `-ㄹ지라도` 33, `-ㄹ찌니라` 461 / `-ㄹ지니라` 51).

처음에는 채택본의 부분 현대화를 의심했다. 제2 소스(scj-peter)를 대조하니
시편 4:3·116:7이 **둘 다 "찌"**여서 의심이 굳어지는 듯했다.

**대한성서공회 사이트가 정반대를 확인했다.** 시편 116:7은 공식 표기가
"돌아갈**지**어다"이고, 시편 46:10은 "알**찌**어다"다 — **둘 다 맞다.**
개역한글 원문 자체가 이 어미에서 일관되지 않으며, 채택본은 그 불규칙성까지
그대로 보존하고 있다.

> **첫 세션의 판정 방향이 이 구간에서는 뒤집힌다.** 그때는 제2 소스가
> `-ㄹ찌라도`를 263→2로 **현대화**했다고 보았다. 여기서는 반대로 제2 소스가
> "지"를 "찌"로 **과잉 복고화**했다. 어느 쪽이든 제2 소스는 손을 댔고,
> 채택본만이 원문을 건드리지 않았다.
>
> 그래서 이 발견은 채택본의 결함이 아니라 **신뢰도를 높이는 증거**다.
> 규칙적으로 보이도록 정리하지 않았다는 뜻이기 때문이다.

실무 지침: **"지"로 되어 있다고 해서 현대화 오류로 판단하지 말 것.**
의심되면 대한성서공회 사이트에서 해당 절을 직접 확인한다. 두 소스의 다수결은
이 문제에서 답이 되지 않는다.

### 5. 절 합본 구간 — 19개, 범위 ref로 쓰면 안 된다

4차분 큐레이션(2026-08-18) 중 시편 92:1-2를 조회했더니 같은 문장이 두 번
반복된 177자가 나왔다. 확인 결과:

- 채택본과 제2 소스가 **둘 다** 시편 92:1·2·3에 동일 텍스트를 넣고 있다
- **대한성서공회 사이트도 "1-3"으로 묶어 표시한다**

즉 데이터 결함이 아니라 **원문이 이 구간을 절로 나누지 않는 것**이고,
두 데이터는 합본 본문을 각 절 번호에 복제해 총 절 수(31,102)를 맞춘 것이다.
전체 66권에 이런 구간이 **19개** 있다.

```
1Chronicles 16:12-13   Acts 15:25-26      Deuteronomy 6:18-19
Deuteronomy 15:4-5     Deuteronomy 30:9-10  Ezekiel 24:4-5
Ezekiel 25:2-3         Isaiah 7:8-9       Isaiah 30:1-2
Isaiah 48:1-2          Jeremiah 21:1-2    Jeremiah 32:3-5
Jeremiah 33:10-11      Job 31:33-34       Job 35:10-11
Joshua 2:12-13         Psalms 92:1-3      Psalms 105:5-6
Romans 9:1-2
```

**범위 ref로 조회하면 문장이 반복된다.** `scripts/lib/krv_source.py`의
`verses_in_range()`가 이를 감지해 `RefError`로 막는다. 단일 절 조회는
안전하지만(합본 전체가 그 절에 들어 있다) ref가 가리키는 범위와 본문
내용이 어긋나므로, 이런 구간은 수록 대상에서 빼는 편이 낫다.
발견 시점에 기존 구절 전수를 검사했고 걸린 건은 없었다.

> **이 유형은 앞의 검증 절차가 놓치던 축이다.** 정답지 6구절 대조로도,
> 옛 표기 분포 확인으로도 잡히지 않는다. 두 소스가 같은 결과를 내므로
> 교차 검증으로도 드러나지 않았다. 실제 조회에서 반복된 문장을 눈으로
> 보고서야 발견됐다. 원문 데이터를 교체할 때 이 구간 수(19개)가 유지되는지
> 확인하면 같은 구조인지 빠르게 알 수 있다.

### 6. 채택본도 완벽하지는 않다

전수 비교에서 채택본 쪽이 의심스러운 건도 나왔다
(예: 역대상 3:23 `에료에내` ↔ scj-peter `엘료에내`).
둘 다 고유명사 영역이며, 지금까지 수록한 250구절과는 무관하다.
2차분에서 희귀 어휘가 든 요엘 2:25(메뚜기·늣·황충·팟종이)를 쓸 때
제2 소스와 대조해 일치를 확인했다.

3차분(60구절)에서는 새로 발견된 데이터 문제가 없었다. 옛 표기가 많이
쓰인 차수였는데(`더딜찌라도` 합 2:3, `기다릴찌니라` 롬 8:25,
`하실찌라` 시 138:8, `옮길찌라도` 사 54:10, `잠잠할찌니라` 합 2:20,
`파숫군` 시 141:3·시 130:6) 추출·대조 전 구간에서 이상이 없었다.

기록해 두는 이유는 원칙 때문이다: **이 데이터는 "무오한 원본"이 아니라
"현재 확보 가능한 최선의 기준"이다.** 대조 결과가 불일치로 나왔을 때
자동으로 `verses.yaml`을 고치지 않는 것(`verify_verses.py`가 diff만 출력하는 것)은
이 한계를 전제한 설계다. 원문 데이터가 틀렸을 가능성이 사람의 판단 대상으로 남는다.

고유명사가 많은 구절을 향후 수록할 때는 그 건에 한해 별도 확인을 권한다.

2. **성명표시권** — 앱에 `성경전서 개역한글판, 대한성서공회`를 표기한다 (Phase 3).

## 갱신 절차

원문 데이터를 교체할 때는 다음을 모두 다시 한다.

1. 정답지 6구절 대조 (위 표) — 한 건이라도 어긋나면 채택하지 않는다
2. 옛 표기 분포 확인 (`-ㄹ찌라도`, `-ㄹ찌니라`, `세째`, `네째`)
   — 단, `-ㄹ지어다`가 섞여 있는 것은 정상이다 (4절 참조). 이것까지
   `-ㄹ찌어다`로 통일된 데이터는 오히려 손을 댄 것이므로 채택하지 않는다
3. 절 합본 구간 수 확인 — 연속된 절이 동일 본문인 구간이 19개인가 (5절 참조)
4. 이 문서의 커밋·sha256·확보일 갱신
5. `python scripts/verify_verses.py --check` 전체 재실행 —
   기준이 바뀌었으므로 기존 `verified: true`도 전부 다시 판정된다
